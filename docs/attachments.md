# 附件与缓存

面向使用者：附件能传什么、传上去存在哪、什么时候会被删、出错了怎么办。

## 支持什么

| 类型 | 处理方式 |
|---|---|
| 图片（PNG / JPEG / GIF / WebP / BMP） | 直接作为图片输入模型。超过 2000×2000 或 4.5MB（base64）会被**自动压缩**，不会报错 |
| PDF | 本地抽取文本后随消息发送（表格按原文保留，扫描件抽不出字） |
| .docx / .xlsx / .pptx | 本地抽取文本（含表格单元格、幻灯片页码） |
| 纯文本（.md / .txt / .csv / 代码等） | 原文内嵌 |
| 其他二进制 | 直接拒绝，并说明不支持这种格式 |

一份附件抽出的文本上限 **1MB**（整条消息合计 2MB）。截断时会明确标注「内容已截断」，不会静默丢内容。

## 上限

| 项 | 上限 | 说明 |
|---|---|---|
| 单条消息附件数 | 10 个 | 图片与文件共用名额 |
| 单条消息合计 | 40MB | 防止一次性把请求撑爆 |
| 单个文件 | 512MB | 流式落盘，不整体读进内存 |
| 单个会话累计 | 2GB / 50 个 | 超了会提示，先清理旧附件 |
| 单文件对话解析 | 64MB | 更大的附件能上传但无法在对话里解析，会明确拒绝 |

## 文件存在哪

```
~/.atrading/attachments/<会话 id>/
├── <附件 id>          原始字节
└── <附件 id>.json     元信息（原始文件名、大小、类型、时间）
```

- 附件在**点击发送时**才上传，选完不发不会占空间。
- 上传有进度百分比，并有取消按钮（发送键位置会变成 ✕）。取消后附件仍在输入框里，可直接重发。
- 消息里只带附件 id，不再携带文件内容本身——所以同一个会话聊得再久，请求体也不会因为历史图片而越来越大。
- 桌面端与 Web 端共用同一个目录（`OPENATRADING_HOME` 可整体改根目录）。

## 什么时候会被删除

| 触发 | 范围 |
|---|---|
| 删除会话 | 该会话的**全部**附件目录立即删除 |
| 孤儿清扫 | 启动时 + 每 6 小时一次：删除「会话已不存在 **且** 静默超过 24 小时」的目录 |
| 设置 → 缓存 → 清除缓存 | 删除全部临时缓存（含所有附件）。会话记录、角色、模拟盘数据不受影响 |

清扫的两条保守规则值得知道：

- 刚上传、还没发出消息的附件**不会被当成孤儿**（会话文件是第一条消息才创建的，所以给 24 小时静默期）。
- 会话还在的附件一律保留——即使放很久也不删，要删由你手动清。

## 正在被使用的附件不会被误删

点「清除缓存」时，如果某个附件正在被一轮对话读取，它会**跳过**并在结果里注明「正在使用中，已跳过」。其余文件照常清理。

## 常见问题

**「附件 xxx 不存在或已失效，请重新上传」**
附件已被删除（清了缓存、删了会话，或清扫判定为孤儿）。重新添加一次即可。

**「超过对话解析上限 64MB，请拆分后再发」**
文件能上传但解析不动。拆成几个小文件，或先把需要的部分导出成更小的 PDF。

**「附件合计不能超过 40MB」**
一次发太多。分成几条消息发，或先压缩图片。

**图片发上去变糊了**
2000px / 4.5MB 是模型侧的限制，超过就会被压缩（这是所有主流模型的做法：OpenAI 2048px、Claude 1568px 起）。要看细节请先裁剪到需要的区域再发。

**桌面端拖入文件**
拖拽走的是「按路径直读」，不经过浏览器内存，大文件比文件选择器更快。拖入的图片只显示文件名不显示缩略图（缩略图需要先把整张图读进内存，与「大文件不占内存」的目标冲突）。
