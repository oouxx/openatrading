# ADR-0002: 操作计划是产品的核心物件，复盘是其生产过程

**状态：** 已接受
**日期：** 2026-06-19
**关联：** docs/ai-native-desktop-plan.md, ADR-0001
**取代/修正：** 无（细化 ADR-0001 的边界，不推翻）

## 背景

grilling 中用户澄清"操盘"的真实含义：**不是盘中 AI 实时决策，而是复盘时预先制定操作计划，盘中按计划执行**。这化解了"AI 操盘"与 ADR-0001（AI 不下结论）之间的表面冲突——结论在复盘阶段就由用户拍板，盘中只是执行预设计划，AI 不做实时决策。

但这个澄清同时暴露了一个此前所有讨论都没触及的核心物件：**操作计划**。

## 决策

**操作计划（Operation Plan）是产品的核心领域物件。复盘是它的生产过程，盘中执行是它的消费过程。**

- 复盘的**终点不是"看懂数据"，是产出一个操作计划**。
- 操作计划由用户在复盘阶段、在 AI 向导辅助下**自己制定**（遵守 ADR-0001：AI 给路径，用户拍板）。
- 盘中阶段是**计划执行器**：按计划监控触发条件、提示用户、不替用户做计划外的实时决策。
- 产品的数据模型、会话、持久化都应以操作计划为中心组织，而非以"对话"或"复盘报告"为中心。

## 影响与取舍

- **重心偏移：** 产品叙事从"AI-Native 复盘工具"变为"复盘 → 计划 → 执行的闭环工具"。复盘只是入口，操作计划才是用户真正持有和复用的资产。
- **对原计划的影响：**
  - Phase 1（布局 + artifact）：✅ 保留，但右侧工作区除"数据视图"外，必须新增"操作计划视图"作为一等公民。
  - Phase 2（AI 调用桌面 API / artifact）：需新增"AI 帮用户把复盘结论结构化成操作计划"的能力——这是 AI 向导角色的延伸（铺路径的终点是生成计划草稿，用户确认）。
  - Phase 3（推送）：盘中推送的语义变了——不是"AI 分析结论"，是"操作计划的触发条件命中"（如"XX 高开，计划关注"）。这把 Phase 3 从"内容推送"重定义为"计划触发器"。
- **新领域概念待定义（留给后续 grilling / glossary）：**
  - 操作计划的结构（标的、触发条件、动作、止损、仓位？）
  - 计划的执行状态机（待执行 / 已触发 / 已跳过 / 已超时）
  - 计划与复盘会话的关系（一次复盘产出一个计划？还是多个？）

## 待解决

操作计划的具体结构、状态机、与复盘/执行两阶段的衔接协议，尚未定义。这是下一道 grilling 关卡的核心。
