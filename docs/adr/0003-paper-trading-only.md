# ADR-0003: 产品是模拟盘系统，永不接真实实盘

**状态：** 已接受
**日期：** 2026-06-19
**关联：** ADR-0001, ADR-0002, docs/ai-native-desktop-plan.md
**修正：** 终结 grilling Front 4-5 关于"操盘/下单/执行"的语义混乱

## 背景

grilling 中用户多次在"操盘/下单/自动"等词上产生表面矛盾的表述（"非自动化交易" vs "AI 策略操盘"、"轻量级" vs "全自动"、"F3 自动下单" vs "模拟撮合"）。最终澄清根因：所有"下单/操盘/执行"都指的是**模拟盘内的模拟撮合**，不是真实券商下单。用户明确："我这个系统就是要做模拟盘，不接真实实盘"。

## 决策

**产品是模拟盘系统（paper trading），执行后端是模拟撮合引擎，永不接真实券商实盘。**

- 复盘阶段：用户在 AI 向导辅助下制定操作计划（ADR-0002）。
- 执行阶段：模拟撮合引擎按计划在盘中**自动撮合虚拟成交**，维护虚拟账户的持仓/资金/盈亏。
- 全程不接券商、不碰真钱、不产生真实交易。所有"下单""成交""持仓""盈亏"均指模拟盘内的虚拟记录。
- 产品边界明确：**不追求通往实盘**。不做券商对接、不做实盘风控、不做真实资金管理。若未来要接实盘，那是另一个产品。

## 影响与取舍

- **终结语义混乱：** "自动下单""操盘""执行"在本产品语境下一律指模拟盘内的模拟撮合，不指真实交易。后续所有文档/对话统一此口径。
- **ADR-0001 保留且加强：** AI 是向导，不替用户做真实决策——模拟盘里"决策"就是用户制定计划，AI 只铺路径。模拟撮合是"跑用户已定的计划"，不是 AI 决策。
- **ADR-0002 保留且具体化：** 操作计划的核心地位不变，且现在明确——计划的"执行"= 模拟撮合引擎按计划撮合虚拟成交。
- **工程量收敛：** 放弃券商对接/实盘风控/撤单滑点等重工程。执行端只需一个**模拟撮合引擎**（取实时行情 + 按撮合规则记虚拟账），工程量可控。
- **对原计划 Phase 的影响：**
  - Phase 1（布局 + artifact）：✅ 保留，右侧工作区需含"操作计划视图"和"模拟账户视图"。
  - Phase 2：新增"模拟撮合引擎"和"AI 帮用户把复盘结论转成可执行计划"两块核心能力。
  - Phase 3：盘中推送语义 = "操作计划的触发条件命中，已模拟撮合/待模拟撮合"，不再是"AI 分析结论"。
